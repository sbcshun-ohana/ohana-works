## 3. 本番データ curation(適用後)

### 3.1 午睡・連絡帳の必須対象を 0〜2歳のみに
staging は全クラス `family_daily_report_required=true`(=`nap_check_required` も true)。**本番は 0〜2歳クラスのみ true にする**。
- [ ] 現況確認:
  ```sql
  select o.name, cc.class_name, cc.age_group, cc.family_daily_report_required, cc.nap_check_required
  from childcare_classes cc join offices o on o.id=cc.office_id where cc.is_active order by o.name, cc.age_group;
  ```

- [ ] 3歳以上クラスを false に(必要な施設のみ):
  ```sql
  -- 例: 家庭連絡帳・午睡チェックを 0〜2歳のみ必須にする
  update childcare_classes set family_daily_report_required = (age_group in ('0歳','1歳','2歳')),
                               nap_check_required          = (age_group in ('0歳','1歳','2歳'))
  where is_active;
  -- ※ age_group の実表記に合わせること(本番が '0歳児' 等なら条件を調整)
  ```

### 3.2 大原利奈 を director → executive_director に切替
- [ ] 対象確認:
  ```sql
  select e.id, e.name, e.employee_number, r.code, er.office_id
  from employees e join employee_roles er on er.employee_id=e.id join roles r on r.id=er.role_id
  where e.name like '%大原%';
  ```
- [ ] 切替(director を外し executive_director を全施設付与):
  ```sql
  -- <emp> は上で確認した employees.id
  delete from employee_roles where employee_id='<emp>'
    and role_id=(select id from roles where code='director');
  insert into employee_roles (employee_id, role_id, office_id)
  values ('<emp>', (select id from roles where code='executive_director'), null)
  on conflict (employee_id, role_id, office_id) do nothing;
  ```

## 5. ロールバック方針・縮退

### 5.1 分類
- **後方互換・安全(大多数)**: 新テーブル/新RPC/新列/フラグ追加。ロールバック不要、残っても無害。
- **RPC drop+recreate**(163/167/172/178/181 の fetch系, 162 置換): ロールバックは**旧版RPCを再デプロイ**(=1つ前のmigrationのRPC定義を再適用)。データ非破壊。
- **RPC create or replace(drop不要)**(183 の nap_interval系 / fetch_nap_board / import_nap_times_to_contact): 戻り型不変のため drop なし。ロールバックは同様に**旧版RPC(181)を再適用**。データ非破壊。
- **バックフィル(データ)**: 166(child_daily_contacts.published_at)・181(nap_intervals)・182(クラス改名/児移し替え)。
  - 166: `update child_daily_contacts set published_at=null where ...`(承認済み即時可視の旧挙動へ戻す)で概ね復旧可。
  - 181: nap_intervals を消しても nap_sessions.sleep_start/wake は残る(バックフィル元)。RPCを旧版へ戻せば旧動作。
  - 182: **本番が既に実名なら no-op**なので通常ロールバック不要。万一改名した場合は逆UPDATEで戻せる(児移し替えは在籍行の end_date/新規行を手動是正)。
- **挙動変更**: 147(manages_childcare に executive_director/area_manager)。ロールバック=旧定義を再デプロイ。

### 5.2 問題発生時の縮退(素早い安全化)
- [ ] **機能フラグOFF**: therapy_outing_enabled / childcare_home_enabled 等を false に(override upsert enabled=false)→ その機能の導線が即座に消える。
- [ ] **cron停止**(暴走時): `select cron.unschedule('<jobname>');`(例: publish_due_daily_contacts / dispatch_scheduled_guardian_notices)。
- [ ] **プッシュ全停止**: Vault の dispatch key を無効化 or dispatch_pending_notifications を unschedule。
