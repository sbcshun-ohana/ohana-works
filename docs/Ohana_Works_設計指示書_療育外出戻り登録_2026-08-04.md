# Ohana Works 設計指示書 — 療育等による一時外出・戻りの時刻登録

作成日: 2026-08-04 / 作成: 俊 + Claude(Fable) / 実装: Claude Code

---

## 0. 目的と位置づけ

- 登園中の園児が療育を併用する場合に、一時的な外出時刻と戻り時刻を記録する機能。
- 目的は登降園の状況管理ではなく、**外部の療育事業者との連携における保育・保護責任の線引きの記録**である。この目的を実装判断の基準とする(例: 通知や承認フローを足すより、正確な時刻記録と改ざん耐性を優先)。
- 既存規約(RLS3ドメイン分離、機能フラグでデフォルトOFF、notifications outbox、マイグレーション採番=着手時点の最新+1、staging→本番フロー)は前回指示書`docs/Ohana_Works_設計指示書_ホーム画面_デイリーボード拡張_午睡チェック_クラス活動Instagram_2026-08-03.md`(以下「前回指示書」)の§0と同一。本書は前回指示書への追補であり、§4で前回指示書の一部定義を改訂する。

## 1. 確定仕様の要約

| 項目 | 確定内容 |
|---|---|
| 対象園児 | 一部の園児のみ。園児マスタで対象設定(適用期間つき) |
| 利用頻度 | 週1〜2日程度。頻度前提の最適化(常時表示など)は不要 |
| 打刻方法 | 紙に印刷した固定QRを既存の玄関キオスク(保護者用と同じ端末)にかざす |
| QRの単位 | 園児×療育事業所ごとに1枚。時間更新(回転トークン)は不要 |
| かざす人 | 療育事業者の送迎スタッフ |
| 外出/戻り | 1枚のQRで交互に切り替わる(外出中でなければ外出、外出中なら戻り) |
| 立会記録 | 不要。QR打刻の時刻記録だけで完結 |
| 保護者通知 | 送らない |
| デイリーボード | 「療育外出中」バッジを表示。サマリーの「登園中」から外出中を除外(§4) |
| 引き渡し先 | 療育事業所を記録する。現状1事業者だが複数事業者・複数事業所利用に備える |
| 修正権限 | 打刻漏れ・誤打刻の修正は主任以上 |

## 2. データ設計

> 権限写像(2026-08-04 俊確定): 事業者マスタ(therapy_providers)の登録/編集=**統括園長以上**(`is_executive_or_system_admin`)。対象園児設定・QR発行/revoke・記録の手動修正=**主任以上**(`manages_childcare`)。2026-08-03 に廃止したのは「施設内業務における管理者以上(主任除外)」区分であり、施設を持たない組織レベルのマスタ(therapy_providers)を統括園長以上に置くことはこの方針と矛盾しない。QRトークンは token_hash のみ保存し、発行時に生トークンを1回だけ返してPDF描画する(紛失時は revoke→再発行、guardian QR と同型)。

### 2.1 テーブル案

- `therapy_providers`(療育事業者マスタ): id, name, is_active, created_at。admin_webから登録・編集(管理者以上)。現状は1事業者の登録で運用開始。
- `child_therapy_settings`(対象園児設定): id, child_id, provider_id, start_date, end_date(nullable=無期限), created_by/at。同一園児×事業所×期間の重複はEXCLUDE制約で禁止(進級一括登録の重複ガードと同じbtree_gistパターン)。
- `therapy_outing_qr_codes`(固定QR): id, child_id, provider_id, token(推測不能なランダム値), revoked_at(nullable), issued_by/at。**紙の紛失に備え、無効化(revoke)→再発行を必須機能とする**。QRのpayloadはtokenのみとし、child_id等の生値を埋め込まない。
- `therapy_outing_events`(打刻記録): id, child_id, provider_id, event_type('out'/'return'), occurred_at, source('kiosk_qr'/'staff_manual'), qr_code_id(nullable), recorded_by(nullable、手動修正時の職員ID), correction_note(nullable), created_at。
- 「外出中」状態は当日のtherapy_outing_eventsから導出する(最後のイベントがoutなら外出中)。daily_child_statusのstatus enumは変更しない(影響範囲を広げないため)。導出ロジックはRPC/ビューに集約し、デイリーボード・キオスク・admin_webで共有する。

### 2.2 RLS

- therapy_outing_events等は保育業務ドメインの既存RLSパターンに従う(保護者からは一切見えない)。
- キオスクからの打刻はEdge Function(service role)経由で処理し、anonキーからテーブル直接書き込みは許可しない(既存resolve-guardian-qrと同じ構え)。

## 3. キオスクの読み分けと打刻フロー

### 3.1 読み分け

- 既存玄関キオスクのQRスキャナで、保護者QR(回転トークン)と療育QR(固定トークン)を読み分ける。payloadにプレフィックスを付けて判別する(例: 療育QRは`therapy:`+token。既存保護者QRのpayload形式は変更しない)。
- resolve処理は新Edge Function `resolve-therapy-qr`(仮称)として実装し、resolve-guardian-qrには手を入れない(責務分離・回帰リスク回避)。

### 3.2 打刻時のバリデーション(Edge Function内)

上から順に判定し、拒否時はキオスク画面に短い理由を表示する:

1. tokenが存在し、revokeされていないこと
2. child_therapy_settingsの適用期間内であること(当日基準)
3. 園児が当日「登園中」であること(daily_child_status=present)。未登園・降園済みは拒否
4. トグル判定: 外出中でなければ`out`、外出中なら`return`を登録
5. 連続かざし対策: 直前のイベントから60秒以内の同種打刻は無視(二重読み取り防止)

### 3.3 キオスク画面表示

- 成功時: 「○○ちゃん 療育外出 12:45(事業所名)」/「○○ちゃん おかえりなさい 14:30(事業所名)」のような確認表示を数秒表示する。敬称は既存のhonorific_suffix_resolvedを使用。
- 保護者への通知は一切送らない(notificationsに行を積まない)。

## 4. デイリーボードへの反映(前回指示書§2.2の改訂)

- 療育外出中の園児の行に「療育外出中」バッジを表示する(外出時刻も添える)。戻り登録で消える。
- サマリー定義を以下のとおり改訂する。**前回指示書§2.2の「登園中」の定義をこの表で上書きする**(実装済みの場合は修正、未実装の場合は最初からこの定義で実装):

| 項目 | 定義(改訂後) |
|---|---|
| 在籍 | その日時点の在籍人数 |
| 登園予定 | 在籍のうち欠席連絡が入っていない人数 |
| 出席 | その日一度でも登園した人数(降園済み・療育外出中を含む) |
| 欠席 | 欠席連絡が入っている人数 |
| 登園中 | いま園内にいる人数(登園済み・未降園、**かつ療育外出中でない**) |

- 「出席」は変更なし(療育外出しても当日出席したことに変わりはない)。

## 5. admin_web

### 5.1 対象園児の設定(園児マスタ拡張)

- /childcare/childrenの園児行に「療育設定」ボタンを追加(連絡帳必須の期間設定モーダルと同じUXパターン)。事業所の選択+適用期間(開始日・終了日)を設定できる。設定は複数行持てる(将来の複数事業所併用に対応)。
- 設定権限は管理者以上。

### 5.2 QRの発行・印刷・無効化

- 療育設定モーダル(または専用画面)から、園児×事業所のQRを発行しPDFで印刷できるようにする。PDFには園児名(敬称つき)・事業所名・発行日・園名・「療育送迎用」の表記とQRを載せたA6〜A5程度のカードレイアウトとする。
- 「無効化して再発行」ボタンを設置(紛失時)。無効化済みQRをかざした場合はキオスクに「無効なQRです。職員にお声がけください」を表示。

### 5.3 記録の閲覧・修正・出力

- 療育外出記録の一覧画面を新設: 施設・月・園児で絞り込み、外出/戻りのペアと所要時間を表示。片方だけの日(戻り未打刻など)は警告表示。
- 修正・手動追加は主任以上。修正時はsource='staff_manual'+recorded_by+correction_noteを記録し、元レコードは論理的に辿れる形にする(上書きせず訂正履歴を残す)。
- 月次一覧の出力ボタンを設置する(確定仕様): CSVおよびPDFの両形式で、園児別・月別の外出記録一覧を出力できること(監査対応用)。PDFは一覧画面と同じ「外出/戻りのペア+所要時間+片方欠落の警告」を含むシンプルな帳票でよい。

## 6. 機能フラグと段階導入

- 機能フラグ(例: `therapy_outing_enabled`)でデフォルトOFF。対象園児が実在する施設のみONにする。
- OFFの施設ではキオスクの読み分け・デイリーボード表示・admin_web導線のすべてが現れないこと。

## 7. 実装手順と受入基準

1. マイグレーション(§2のテーブル+RLS+導出RPC)→ staging適用
2. Edge Function `resolve-therapy-qr` 実装(バリデーション§3.2)
3. admin_web: 事業者マスタ・療育設定・QR発行PDF・記録一覧/修正
4. キオスク: payload読み分け+確認表示
5. デイリーボード: バッジ+サマリー定義改訂(前回指示書Phase 2と実装順が前後する場合はどちらが先でも最終定義が§4になるよう調整)

受入基準:
- 対象園児のQRで「登園中→外出→戻り」のトグルが正しく動き、eventsに事業所つきで記録される
- 未登園時・適用期間外・revoke済みQRの3パターンが正しく拒否され、理由が表示される
- 二重読み取り(60秒以内)が1件しか記録されない
- 外出中はデイリーボードにバッジが出て「登園中」人数が1減り、「出席」は変わらない。戻りで元に戻る
- 保護者アプリに通知・表示が一切出ない(保護者02アカウントで確認)
- 一般職員では修正操作ができず、主任以上で修正でき、訂正履歴が残る
- フラグOFF施設で機能が一切露出しない
- 記録一覧から月次のCSV・PDFが出力でき、外出/戻りペア・所要時間・片方欠落の警告が含まれる

検証はstagingで行い、完了報告に実ロールへの権限写像と検証結果表を含めること。
